Documents 01–07 describe the base product, 08–12 specify HPE, 13–19 specify extensions and 20 defines board acceptance. ## Integration decisions

1. Apply the board measurements in ADR-026 to document 20 and its JSON board profile. The expander uses the CH32V003 register protocol at 0x24. EXIO5 low selects USB, EXIO3 resets the LCD and EXIO2 enables the backlight. Carry forward the 30 MHz panel timing and ADR-035 scan-out configuration. Measure any alternative with the same load. [Board revision](ADR-026-target-board-7b.md) · [Scan-out](ADR-035-scanout-stability.md)
2. Reserve one static USB configuration for the four-interface candidate. IF0/0x81 and IF1/0x82 remain report-ID-free Boot Keyboard and Boot Mouse. IF2/0x83 gains Precision Touchpad 0x10..15. IF3/0x84 IN and 0x05 OUT carries Radial 0x20, Consumer 0x21 and Studio 0x22..24. Allocate the optional 12-byte joystick report 0x30 within IF3. The current build has Consumer on IF2 with three data IN endpoints. Moving it changes the host-visible descriptor. Gate this change on parsed descriptors, a compatibility identity/migration decision, release behavior, and the host matrix before advertising a new capability. Profile changes release inputs within the existing USB session. [Current transport](../../components/usb_hid_device/src/usb_hid_device.c)
3. Keep a single touch reader, LVGL owner, InputArbiter and HID scheduler. Route profile actions through typed intents and local grants. Local takeover, revoke, view exit and disconnect invalidate the lease, cancel touches, release held inputs and end capture. The HOST service runs on the computer attached to USB. The existing Windows CLIENT operates on a separate computer and has a feedback-loop guard.
4. Use the package's three JSON Schemas for desktop authoring. The three example source profiles and schemas are in `tools/kvmpack/`. An unsigned desktop build contains sorted payloads and an `integrity.json` mapping each relative path to its byte length and SHA-256. Consumer-side schema, action, integrity, capability and physical approval checks must also run on the device. The desktop tool verifies signed input against an explicitly supplied Ed25519 public key. The signed message prepends the versioned domain separator to each sorted member name, length and SHA-256 digest. The firmware rejects signed archives until a publisher trust anchor is provisioned. Runtime grants are bound to the pack, host, resource and session.
5. Store installed extensions on **microSD**, as selected by the owner on 2026-11-19. Both 4 MiB application slots and the 0x7B0000-byte IME partition are in use. The 128 KiB diagnostic reserve cannot contain one maximum-size default pack (256 KiB compressed, 2 MiB expanded). Under `KVPACKS`, use the eight consecutive eight-hex-digit segments of SHA-256(profile ID) as the directory path. Keep two payload/index pairs, `A.KVP/A.IDX` and `B.KVP/B.IDX`. An index holds `KVP1`, a positive u64 LE generation, the 32-byte payload digest and an IEEE CRC32 LE over those fields. Serialize writers, sync the inactive payload before its index, and check both slots on recovery. A valid index identifies a storage candidate. Before activation, verify the profile ID, pack contents, device-owned grants and health. Retain the previous working snapshot through the health check. On removal, read failure or failed recovery, cancel the profile, release HID, stop and clear media, and display firmware-resident Home. Reinsertion requires fresh validation and capture consent. Use the vendor's one-bit SDMMC routing (CLK 12, CMD 11, D0 13), with mount formatting disabled. Test card removal during reads/writes and measure detection latency. [Current partition table](../../partitions.csv)
6. Preserve the two UI coordinate spaces. The HPE shell has a 40 px header and 68 px navigation area with 1024×492 content. An immersive pack has a system-owned 32 px bar and 1024×568 content. Keep Home, connection state and capture/Stop controls reachable. Media profiles and the H.264 research handoff have additional acceptance criteria. [ADR-041](ADR-041-live-media.md)

## Desktop commands

Use Python 3 with `jsonschema` 4.x (Draft 2020-12). The following commands run from the repository root. Build to a new filename. The default cap is 256 KiB per archive.

```sh
python tools/kvmpack/kvmpack.py validate tools/kvmpack/examples/flight-yoke
python tools/kvmpack/kvmpack.py build tools/kvmpack/examples/flight-yoke -o ../evidence/flight-yoke.kvmpack
python tools/kvmpack/kvmpack.py inspect ../evidence/flight-yoke.kvmpack
python tools/kvmpack/kvmpack.py preview ../evidence/flight-yoke.kvmpack -o ../evidence/flight-yoke.html
python test/kvmpack/test_kvmpack.py
```

`python tools/kvmpack/kvmpack.py stage PROFILE --card MOUNT` writes a versioned installer to the card root. Select **Install from card** on the panel to review it. For a paired Windows CLIENT, open **Receive from paired client** on the panel and use **Install to paired device…** in Studio or `kvmpack.py install --device PAIRED_ID ARCHIVE`. The authenticated transfer ends at the same local permission review. [CLIENT instructions](../../clients/windows/README.md)

## Device workflow

Tap **Extensions** at the top left of Mouse. **Installed extensions** lists profiles under `KVPACKS`, **Install from card** lists `.kvmpack` files at the card root and **Video files** lists `.mp4`, `.h264` and `.264` files there. **Device tools** opens the HOST and HID controls. Inside a category, **Extensions** returns to these choices and **Home** returns to Mouse. Select a package to review its permissions, then tap **Install and open**. To remove an installation, select its installed entry, tap **Uninstall** and confirm. Home and card removal release the current profile. The read-back of the inactive slot completes before the new index becomes active.

The firmware enables exFAT in the pinned FatFs component at build time and disables automatic formatting. The RAM card fixture uses the same mount implementation, reads only the volume label and filesystem information, and unmounts before returning. Physical mounting and removal results belong in the board report.

The browser uses the FatFs UTF-8 API for paths returned by directory enumeration. On the same in-memory exFAT volume, UTF-8 reopened all six long filenames and read their 180,569 payload bytes. The previous OEM encoding reopened only the ASCII name. The video browser listed Polish and Chinese names, found the adjacent prepared file and retained its 100-byte UTF-8 limit. Displaying a particular character also requires a font that contains its glyph. [Filesystem and browser checks](../../../evidence/build/card-utf8/result.json)

After local approval, the card worker writes a tentative `KVT1` index in the inactive slot and verifies the staged payload. The panel constructs the profile and records the time of its first completed refresh. Home remains accessible during the trial and profile actions are disabled. A refresh that completes before the five-second deadline allows the card worker to verify the payload again and publish its `KVP1` index, even if the worker resumes after the deadline. Recovery ignores tentative and torn indices. An interrupted first installation leaves the firmware Home available. An interrupted update preserves the previous healthy generation.

Uninstall writes `OFF.IDX` before it clears either slot. While the marker exists, the profile stays hidden and its old grants, pause setting and activation failures have no effect on a new review. A subsequent installation finishes clearing those records before removing the marker and staging the new package. A fresh installation starts at generation one and tracks its own activation failures.

The desktop and firmware validate static PNG assets, their sizes and SHA-256 digests. The firmware decodes PNG rows within the declared memory budget. The optional Ed25519 signature covers all payloads, including assets, sorted by member name. To accept signed packages, configure the firmware build with `-DKVM_PACK_PUBLISHERS=/path/to/publishers.pem`. The PEM contains one to eight Ed25519 SubjectPublicKeyInfo public keys. The keys are embedded in the firmware. Remove a key in a subsequent firmware build to revoke it on the device, including for previously installed packages. The default build has no publisher keys. [PNG validation results](../../test/reports/2026-11-19_pack-png_022168e4.yaml)

A Button can reference a PNG with `props.icon`, using the exact member name, for example `assets/flight.png`.
The device keeps one thumbnail per referenced asset. It preserves RGB and alpha and samples the image at up to 32 × 32 pixels with its original proportions. On buttons at least 64 × 40 pixels, the icon appears on the left of the caption. The entire button keeps its original action. Smaller buttons retain the centered caption. Referenced thumbnails count toward the declared memory budget alongside PNG decoding.

During permission review the firmware labels an unsigned archive **Unsigned local package**. For a verified signature it displays the full SHA-256 fingerprint of the publisher's raw public key. Installing or opening either package requires local approval. The v1.3.1 UI schema defines no widget that references a PNG. The offline checklist exercises card staging, persistent installation and local state bindings. [Example profile](../../tools/kvmpack/examples/flight-checklist/manifest.json)

The review also shows the SHA-256 of the entire installer and describes the effects of its requested permissions. Optional capabilities have individual checkboxes. The **Allow on opening** summary stays beside the approval button while the details scroll. An unchanged installed archive restores the selections for review. New and updated archives start with all optional capabilities off. If a required local capability is unavailable, the review explains why the profile cannot open. Screen sharing still requires approval for each session on both devices.

The HOST, extension installer and all profiles reuse the board and computer pairing established by the existing CLIENT PIN workflow. An authenticated control session can attach its own HOST listener. The board takes the address from the connection and holds the public leaf and port in RAM until that session closes.

For an authored profile, the panel carries the manifest ID and one locally granted HOST capability to the paired computer. The HOST echoes the scope and displays the profile ID in its consent prompt. Telemetry is limited to the declared topics. Opening the magnifier releases the profile's USB controls. A COMPOSITE profile with both local grants may retain its telemetry subscription while the operator selects and approves a display. Each scope uses its own control connection, token and consent. A HOST using the original handshake closes telemetry before display sharing starts. Stop and Home on the device end both scopes. Changing the display requests fresh capture consent and preserves a negotiated telemetry session. The two Studio command identities remain reserved. [HOST handshake and consent](../../hosts/windows/README.md)

Each installed slot may have a 44-byte `.GRT` file with the exact archive digest, optional selection mask and CRC. The existing 48-byte activation index remains readable. A missing, torn or mismatched preference file starts the review with no optional selections. The firmware saves the selection after the candidate's first successful display refresh. A later opening still requires a local tap. [Storage and review tests](../../test/reports/2026-11-19_offline-packages_022168e4.yaml)

Product builds use the GT911 for local touch. Touch simulation for the input benchmark requires a bring-up build with `CONFIG_KVM_UI_BENCH_TAP` and an active benchmark scene. Performance counters and LCD snapshots remain available independently. [Hardware test guide](../../test/hil/README.md)

Card recovery on the desktop and device reads the newest valid health record in each slot.
If power fails after a version is quarantined but before its index is retired, the next update
preserves the healthy slot. When a mounted card reports an I/O error during browsing, the
device discards the partial listing and returns to Home. An empty directory and an absent
optional video companion remain valid.

The current HOST setup and protocol are documented in the [Windows HOST guide](../../hosts/windows/README.md). The measured package, SD and USB results are recorded in the [storage report](../../test/reports/2026-11-19_offline-packages_022168e4.yaml) and the [HPE report](../../test/reports/2026-11-19_hpe-four-interface_022168e4.yaml).
