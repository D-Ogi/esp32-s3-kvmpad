# ADR-046 · Portrait monitor console as a composable extension

**Implemented for hardware evaluation, 2026-11-20.** A community author should be able to arrange a monitor viewport, an on-screen keyboard and a relative touchpad in one extension. The first package targets the 7B held in portrait, with the same PC supplying the picture and receiving input.

## Layout and touch

Place the monitor at the top, a touchpad with drag and two-finger scrolling below it, and the keyboard within thumb reach at the bottom. Preserve the source aspect ratio. At 600 pixels wide, VGA occupies 600 × 450 and a 1024 × 600 landscape source occupies about 600 × 352. Device orientation and the Windows desktop mode are independent. The keyboard can fold away to enlarge the pad. A side drawer carries occasional controls. The bottom navigation handle opens the extension screen switcher and provides a route to Home. A gesture begun on the pad stays with the pad until release.

## Runtime and transport

The package declares MonitorViewport, KeyboardSurface and TouchpadSurface with independent bounds. Studio previews all three. The runtime owns video buffers, fit, input arbitration, keyboard layout, modifier state and pointer delivery. The manifest declares the capabilities used. Opening a screen alone must never synthesize input. A local action starts the combined USB session. The existing standalone monitor and keyboard views continue to use their respective profiles.

The installed Espressif driver identifies its composite monitor function by VID 303A, PID 2986, MI_00. Prototype it alongside Windows HID keyboard and mouse functions on the same cable. Local USB input requires no HOST launch or new pairing. When the extension closes or its card disappears, the runtime releases held inputs, closes the viewport and restores the ordinary four-interface configuration. Test USB suspend, disconnect and failed profile changes as well as normal exit.

## Acceptance

The monitor viewport accepts up to two changed rectangles for a single picture. In the 584×438 portrait viewport a 16×16 cursor moving diagonally required 741 transferred pixels in the LVGL fixture. A single enclosing rectangle required 107,604. Both renders matched the full panel framebuffer byte for byte. Two other viewport sizes and the unscaled VGA and native views passed the same comparison. [Viewport tests](../../../evidence/build/usb-monitor-motion/console-test.log) · [Unscaled tests](../../../evidence/build/usb-monitor-motion/regular/run.log)

The composite transport prototype passed host-side TinyUSB tests with VGA and native display profiles. Local keyboard and mouse reports were delivered while the vendor endpoint received image data. The tests also covered reset, suspend, neutral input on resume and restoration of the four-interface profile. The card package contains Console and Pointer pages. Pointer expands the touchpad and both pages retain the same VGA viewport. [Composite USB tests](../../../evidence/build/usb-desktop-controls/session.log)

1. Confirm Windows binds the installed display driver and both standard HID drivers concurrently. Show an extended desktop, type into an editor on that PC, drag a window and scroll while the image continues updating.
2. Preview the same authored layout in Studio and on the LCD, for VGA and the native signal, across day, night and high contrast. Check orientation, keyboard target sizes, modifiers, drawer hit areas and gesture ownership.
3. Verify an independent package can rearrange all three widgets without a firmware change. Test missing capabilities, closing with a key or mouse button held, card removal and recovery to all four HID interfaces.

A separate landscape package placed a 440 × 176 keyboard, a 132 × 88 touchpad and a 160 × 120 monitor inside an offset row. The exported browser preview and the native LVGL runtime agreed on all three rectangles in day, night and high contrast. The native test opened the actual archive, selected the native USB signal, started and stopped the simulated monitor, pressed the bottom-right arrow and moved the pointer on the relocated pad. The Windows CLIENT build also opened the bundled portrait example and the independent archive in Studio. Leaving each session restored the ordinary four HID interfaces. On boot 468 the owner installed the portrait extension from the card, saw the desktop with both controls, and confirmed typing in Windows. At that point the USB scheduler recorded 195 accepted inputs, zero refusals and zero timeouts, and the monitor reported 77 presentations. The owner observed clipping at the keyboard edges.
